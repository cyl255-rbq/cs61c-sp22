句话回答：在现代CPU上，即便写最普通的C语言循环，换成“多水桶法"依然会加速！
不过，它加速的原因不再是因为向量指令太重，而是为了喂饱现代CPU的另一个黑科技一一超标量
执行（Superscalar Execution）。
1.现代CPU的秘密：一个周期能做多条加法
你以为的单核CPU：一个周期只能执行一条加法指令。
真正的现代单核CPU：内部焊了3到4个完全独立的标量加法器（ALU）。
这意味着，只要指令之间没有依赖关系，现代CPU可以在同一个时钟周期内，同时执行3到4条普
通的加法指令！这种能力叫做“多发射（Multi-issue）"或“超标量”。
2.传统单水桶：空有战力，无处发挥
当我们写最普通的循环时：
for (int i = 0; i<100; i++) {
sum += a[i]; // sum = sum + a[i]
}
虽然每条加法确实只需要1个周期，转发机制也确实能让下一条加法紧跟其后，不需要Stall。
但是，因为每一行都必须死死依赖上一行的sum结果，这就形成了一条无法打破的“单线因果链”。
o第1个周期：ALUO算sum+a[θ]。此时隔壁的ALU1、ALU2闲着。
o第2个周期：ALUO算sum+a[1]。别的ALU依然闲着。
结果就是：每个周期只能跑1条加法指令。CPU内部其他几个加法器只能坐在那无聊地抠脚。
3.标量多水桶：瞬间唤醒所有加法器
如果我们把普通的C语言循环也展开，并用上四个普通的int水桶：
int sumθ = 0, sum1 = 0, sum2 = 0, sum3 = 0;
for (int i = 0; i < 100; i += 4) {
sumθ += a[i + 0]; // 指令 1
sum1 += a[i + 1];// 指令 2
sum2 += a[i + 2]; // 指令 3
sum3 += a[i + 3];// 指令 4
}
sum = sum0 + sum1 + sum2 + sum3;
这时候，CPU的大门彻底打开了！
当这4条独立的加法指令同时进入CPU的发射队列时，CPU的硬件调度器打量了一下它们：
“哟，这4条指令算的是不同的变量，彼此完全不认识啊！那还排什么队？”
于是，在同一个时钟周期内：
ALUO去算 sume += a[i+θ]
oALU1同步去算sum1+= a[i+1]
oALU2同步去算 sum2 += a[i+2]
oALU3同步去算 sum3+= a[i+3]
原本需要4个周期才能走完的4步加法，现在在1个周期内被4个硬件加法器一拥而上全部解决！
这就是普通的C语言多水桶能加速的本质：它打破了循环携带的数据依赖，释放了单核CPU内部多
个标量计算单元的并发并火能力。

4.现实残酷的真相：为什么我们平时不手动这么写？
既然这么有用，为什么我们平时写业务代码时，很少见到有人把普通循环手写成好几个sum0，sum1?
答案是：因为现代编译器（如GCC,Clang）在开启优化（如-o2或-03）时，智商实在是太高了。
如果你在开启-03 优化时把最简单的sum+= a[i]喂给编译器，编译器在后台不仅会偷偷帮你把
循环展开，不仅会帮你自动变成“多水桶"模式，它甚至会直接嫌标量加法太慢，当场把你的普通C
语言代码升级成SIMD向量代码（自动向量化，Auto-vectorization）。
所以：
O如果你编译时用-00）（不优化）：手写多水桶标量循环，你会看到明显的性能暴涨。
如果你编译时用-03）（最高优化）：你手写不手写都一样了，因为编译器已经帮你把这套体
系结构的底层红利全部吃尽了。
这就完美闭环了。你现在学SIMD和手写优化的意义，正是为了在编译器“失灵”（比如遇到复杂的if-
else导致编译器不敢自动优化）时，你能够亲自扮演那个“无敌的编译器”，用手写多水桶或SIMD去
强行拯救代码的性能！
