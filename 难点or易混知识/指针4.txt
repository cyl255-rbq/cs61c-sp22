将 char 转换为 unsigned char 时，位模式（二进制表示）保持不变，但数值的解释方式改变。具体行为取决于原 char 是有符号还是无符号，以及转换发生的上下文。
1. 如果 char 默认是有符号（常见情况）
假设 char 占 1 字节（8 位），采用补码表示。
原值范围：-128 到 127。
转换为 unsigned char 后，范围变为 0 到 255。
转换规则：
通过模 256 运算将值映射到 unsigned char 的范围内。
即：(unsigned char) x = x % 256（实际就是取其最低 8 位的无符号值）。
示例：
c
char c = -1;               // 二进制 0xFF
unsigned char uc = c;      // 位模式仍为 0xFF，但 uc 的值为 255
底层原理：
有符号 -1 的补码表示是 11111111（0xFF）。
这个位模式作为无符号数解释时就是 255。
2. 如果 char 默认是无符号（少数平台）
此时 char 和 unsigned char 本质相同，转换只是类型上的语法变化，值不会改变。
3. 显式转换 vs 隐式转换
显式转换：(unsigned char) c 或 static_cast<unsigned char>(c) 明确告诉编译器按上述规则处理。
隐式转换：当将 char 赋值给 unsigned char 变量、作为参数传递（若函数期望 unsigned char）时，也会自动发生同样的转换。
4. 常见陷阱与用途
原 char 值		位模式（8位）	转换为 unsigned char 后的值
0			00000000		0
127			01111111		127
-128			10000000		128
-1			11111111		255
转换本身不会修改内存中的二进制表示，只是改变了对该数据的数值解释。这在底层编程中非常重要，因为实际操作的往往就是这些二进制位


在 C 语言中，如果 a 是一个数组（如 int a[10];），那么 &a 表示整个数组的地址，其类型是“指向数组的指针”，例如 int (*)[10]。
打印 &a 会发生什么？
输出一个地址值
&a 的值（内存地址）与 a（数组首元素的地址）在数值上是相等的，都指向数组的起始位置。
因此，printf("%p", (void*)&a) 会输出与 printf("%p", (void*)a) 相同的内存地址（十六进制形式）。
类型不同
a 的类型在大多数表达式中被转换为 int*（指向首元素的指针）。
&a 的类型是 int (*)[10]（指向整个数组的指针）。
尽管地址值相同，但指针运算时的步长不同：a + 1 增加 sizeof(int) 字节，而 &a + 1 增加 sizeof(a)（即整个数组的大小）。
例：
int a[5] = {1,2,3,4,5};
printf("a    = %p\n", (void*)a);
printf("&a   = %p\n", (void*)&a);
printf("a+1  = %p\n", (void*)(a+1));
printf("&a+1 = %p\n", (void*)(&a+1));
输出可能为：
a    		= 0x7fff5fbff7c0
&a  	 	= 0x7fff5fbff7c0
a+1  		= 0x7fff5fbff7c4   // 增加了 4 字节（int 大小）
&a+1 	= 0x7fff5fbff7d4   // 增加了 20 字节（整个数组大小）

在 C 语言中，char 类型本质上是一个整数类型（占 1 字节），它既可以用来存储字符（如 'A'），也可以用来存储小整数（如 -1、100 等）。
所以 char c = -1; 是完全合法的，c 的二进制位模式是 11111111（在补码表示下），这一点没问题。
C 标准将 char 定义为“能容纳基本字符集的类型”，但它同时也是一个整型，与 signed char 和 unsigned char 属于同一类别。因此：
    char 可以存放整数值（范围取决于它是有符号还是无符号，通常默认有符号）。
    字符常量（如 'A'）本质上是 int 类型的整数（ASCII 码），赋值给 char 时会自动截断。
char c1 = 'A';        // 存放字符，实际存的是 65
char c2 = -1;         // 存放整数 -1
unsigned char uc = c2; // 位模式 0xFF 被解释为 255
字符常量（如 'A'）实际上是一个 整型常量，其值等于该字符在字符编码（通常是 ASCII）中的数值。因此：
    char c1 = 'A';
    char c1 = 65;
这两条语句在编译后没有任何区别，c1 存储的都是整数值 65。
背后的原理
    字符集（如 ASCII）将字符映射为整数，'A' 对应 65。
    字符常量在编译时就被转换为对应的整数值。
    char 类型本质上是 1 字节的整数类型，既可以存储字符编码，也可以存储小整数。
注意事项
    虽然数值上等价，但使用字符常量（'A'）比直接写数字（65）更具可读性。
    在某些非 ASCII 环境下（如 EBCDIC），'A' 可能对应不同的数值，但代码的可移植性更好。
所以你的理解完全正确：所有字符在计算机中都是用数字表示的，char 存储的就是这个数字。


char 本身只存储数值（比如 65），并不会自动“映射”到字符 'A'。真正把数值变成屏幕上显示的字符 'A' 的是 输出函数（如 printf）和 操作系统/终端 共同完成的，过程大致如下：
1. 存储阶段
c
char c = 'A';   // 编译器将 'A' 转换为 ASCII 码 65，存入 c
char d = 65;    // 直接存入 65
此时内存中存储的都是二进制 01000001，没有任何字符概念。
2. 输出阶段
当你使用 printf("%c", c); 时：
printf 看到格式说明符 %c，知道要输出一个字符。
它将变量 c 中的数值 65 传递给操作系统或终端。
操作系统/终端根据当前使用的字符编码表（如 ASCII、UTF-8 等）查找数值 65 对应的字形（glyph），然后在屏幕上渲染出 A 的形状。
关键：这种映射不是 char 类型的功能，而是由 输出设备（终端、控制台）的字符渲染引擎 根据编码表完成的。不同的编码表下，同样的数值可能显示为不同字符（例如在 ASCII 中 65 是 A，在 EBCDIC 中可能是其他字符）。
3. 输入阶段
类似地，当你在键盘上按下 A 键：
操作系统收到按键事件，根据键盘映射和字符编码，将按键转换为数值 65。
如果使用 scanf("%c", &c);，则 65 被存入 c。
4. 为什么看起来像是 char 直接映射？
因为编程语言和标准库将字符常量和 I/O 函数设计得很自然，让开发者感觉 char 就是字符。但底层实际上是整数值加上编码表的转换。

因此int c = 'A'; 和 int c = 65; 效果完全相同，printf("%c", c) 都会输出字符 'A'。

在 printf 中使用 %c 时，C 标准规定：参数会先被提升为 int，然后转换为 unsigned char，最后输出对应的字符。所以 %c 不仅适用于 char，也适用于任何整数类型（但只取低 8 位）。
当 char c = 257; 或 char c = 100000000; 时，由于 char 类型只占 1 字节（8 位），赋值会发生溢出截断：实际存储的值是原数值对 256 取模后的结果（即最低 8 位）。
1. char c = 257;
    257 % 256 = 1
    内存中存储的二进制为 00000001
    printf("%c", c); 输出 ASCII 码为 1 的字符，即 SOH (Start of Heading)，这是一个控制字符，终端上通常不可见（或显示为乱码/空格）。
2. char c = 100000000;
    100000000 ÷ 256 = 390625 余 0
    100000000 % 256 = 0
    内存中存储的二进制为 00000000
    printf("%c", c); 输出 ASCII 码为 0 的字符，即 空字符 '\0'，终端上同样不可见（不会显示任何内容）。

在 C 语言中，printf 使用 %c 时，参数的处理分为两个阶段：
默认实参提升（在调用 printf 之前发生）
对于可变参数（...），小于 int 的整数类型（如 char、short）会被提升为 int。
提升是值保留的，不会截断。例如 char c = -1; 提升为 int 时，值仍然是 -1（32 位下表示为 0xFFFFFFFF）。
printf 内部转换（根据 %c 说明符）
C 标准规定：%c 对应的参数（已经是 int）会被转换为 unsigned char，然后输出其对应的字符。
转换为 unsigned char 时，会取该 int 值的低 8 位（即对 256 取模），这就是截断发生的地方。
为什么不早一点截断？
提升阶段只是为了让参数在可变参数传递时有一个统一的类型（int），并不会改变数值大小。如果提升时就截断，会导致 char 类型传入时丢失符号信息，而实际需要的是保留符号以进行正确的算术转换（例如 %c 接受任何整数，最终只关心低 8 位）。因此，截断被推迟到 printf 内部根据格式说明符 %c 进行。
例子说明
在 C 语言中，对于可变参数函数（即参数列表中有 ... 的函数，如 printf），调用时会执行默认实参提升。这是 C 标准规定的一个规则，原因主要有以下几点：
1. 简化函数调用约定
可变参数列表在编译时不知道具体类型，因此调用者需要按照统一的规则传递参数，以方便被调函数（如 printf）按固定方式读取。
默认实参提升将所有小于 int 的整数类型（char、short 等）提升为 int（或 unsigned int），将 float 提升为 double。这样，所有整数参数在栈上至少占用 int 的大小，所有浮点参数至少占用 double 的大小，参数传递的格式变得一致。
2. 避免类型不匹配导致的错误
如果没有提升，传递一个 char 给 ... 时，它的实际类型是 char，但被调函数可能按 int 来读取，就会读错（例如读取了相邻的字节）。
提升后，无论原始类型是 char、short 还是 int，被调函数都能以 int 的方式安全地访问参数（因为实际传递的就是 int）。
3. 历史原因与兼容性
早期的 C 语言（K&R C）函数参数没有原型，调用时默认对所有参数进行提升。这种机制延续到了标准 C 中，以保持向后兼容。
4. 性能考虑
在大多数硬件上，按 int 或 double 大小传递参数比按更小的类型更高效，对齐也更容易。
