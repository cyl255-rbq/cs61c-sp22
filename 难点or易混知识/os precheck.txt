1.操作系统的职责包括加载程序、处理服务（例如网络协议栈和文件系统）以及为多个程序复用资源、
以及将程序彼此隔离，以防止某个程序干扰另一个程序的内存或执行。

2.管理员模式的目的是将某些指令和例程与用户程序隔离开来。
正确。管态（Supervisor Mode）（也叫特权模式）的目的是将某些指令和例程与用户程序隔离开来。
如果程序出现 Bug 或恶意行为，由于操作系统控制着所有资源，管态可以限制该程序对计算机的影响。

3.用户程序通过系统调用来调用操作系统例程。
没错。系统调用（Syscalls）允许用户程序在切换回用户模式之前，先进入管态执行操作系统的例程。
唯一合法接口： 用户程序想读文件、想发网络包，自己没权限做，必须通过 ecall（RISC-V）或 
int 0x80（x86）这类指令向 OS 发出请求，这就像是“过海关”，必须接受 OS 的检查。
这句话描述的其实是一个"三步走"的闭环：
第一步：触发系统调用
用户程序执行到一半，发现需要读写文件或联网。它不能直接操作硬件，于是执行一条特殊指令
(比如RISC-V里的ecall）。
这就像你在柜台前敲了敲玻璃：“请帮我取100块钱。“
第二步：进入管态并执行例程（这句话的核心）
这时，硬件会自动切换状态：
1．权限升级：CPU从用户模式切换到管态。
2.执行OS例程：CPU跳转到操作系统预先写好的代码（例程）去运行。操作系统会检查：你
有权限读这个文件吗？硬盘现在有空吗？
3．完成任务：操作系统亲自操作硬件，完成了读写任务。
第三步：切换回用户模式
任务完成后，操作系统不能一直占着CPU权限。它会：
1．权限降级：把CPU状态切回用户模式。
2.返回结果：把读到的数据交给用户程序，让它接着往下跑。

4.TLB 是页表的缓存，所以一个条目可能在页表中是有效的，但并未存储在 TLB 中。缺页异常发生在：
页表里找不到该页，或者该页的有效位（Valid bit）为 0。
三级缓存逻辑： CPU 先查 TLB（快）；没中（TLB Miss），再查内存里的 Page Table（慢）；
如果页表里显示该页在磁盘上（Valid=0），才叫 Page Fault（极慢）。

6.内存映射的实现可以使用中断驱动的 I/O（例如，读取文件）。
DMA 并不是取代了轮询或中断，而是为了减少 CPU 的参与。 实际上，DMA 往往需要和“中断”配合使用。
1.为什么会有DMA(Direct Memory Access, 直接内存访问)？
在只有轮询或中断的情况下，数据搬运是这样发生的：
轮询/中断：硬件CPU寄存器内存。
：问题：如果要搬运1GB的数据，CPU必须亲自执行几亿次1w(加载)和sw(存储)指令。
这太浪费CPU这个"超级大脑"的精力了。
DMA的引I入：
DMA是主板上的一个"小助手"。CPU只需要告诉它："把磁盘从A地址开始的1MB数据搬到内存
B地址去，搬完了叫我。”然后CPU就去干别的了。
2.DMA依然离不开中断
虽然DMA负责搬运数据，但它通常无法独立完成整个I/O流程：
1．开始阶段：CPU设置DMA寄存器（通常通过MMIO，即1.7题讨论的内容）。
2.传输阶段：DMA默默搬运，不占用CPU。
3．结束阶段：数据搬完后，DMA控制器必须通过中断（Interrupt）告诉CPU："活干完了，
你可以处理内存里的新数据了。"
