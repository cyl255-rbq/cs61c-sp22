代码：Point *my_pt = calloc(1, sizeof(Point));
    分配内存：calloc 在堆（Heap）上申请了一块足够存放 Point 结构体的空间。
    自动清零：这是它和 malloc 最大的区别。malloc 申请完内存后里面是“垃圾值”（garbage），而 calloc 会把申请到的所有字节全部初始化为 0。
    现状：此时，my_pt->x 是 0，my_pt->y 也是 0。

void changeX5 (Point *pt) {
    pt = 55; // 这里的 pt 是一个局部变量（指针）
}

free() 函数只能作用于由 malloc 返回的原始指针，而不能作用于指向缓冲区内部的指针。
这有几个原因：
我们可以想象操作系统（OS）记录了所有由 malloc 分配的内存块，但它只存储每个块的起始指针。当调用 free() 时，操作系统会查找它记录的指针，并释放匹配的那一个。
另一种理解方式是：malloc 实际上在你分配的块之前和之后创建了一些“元数据”（metadata）。如果你尝试释放一个位于 malloc 块中间的指针，系统最终会把随机的数据误当做堆元数据来解析，从而导致崩溃或内存损坏。

int main () {
	char *x = malloc(0xFFFFFFFF * sizeof(char));
	x[0] = '!';
}
会引发什么错误，假设系统是32位
当 CPU 执行到 malloc(0xFFFFFFFF) 时：
发出请求：程序跑去问操作系统：“喂，给我 4GB 连续的内存！”
系统拒绝：操作系统看了一眼账本：“我这儿总共才 4GB，扣掉内核和你的代码，哪儿还有 4GB 连在一起的？不行！”
返回信号：malloc 垂头丧气地返回了一个特殊的值：NULL（在 C 语言中，NULL 的数值就是 0）。
x 会指向 0 吗？
答：是的，x 被赋值成了 0。
虽然 malloc 没申请到内存，但赋值符号 = 是铁面无私的。它会把 malloc 扔回来的那个 0 稳稳地存进 x 这个变量里。
此时，x 的值变成了 0x00000000。
我们管这种指向地址 0 的指针叫 “空指针”（Null Pointer）。
为什么接下来的 x[0] = '!' 会崩？
这就是你之前疑惑的“解引用”。请看这个过程：
代码：x[0] = '!'
底层含义：去地址 x + 0 的地方，往那个柜子里塞进一个 '!'。
执行瞬间：
CPU 看了一眼 x，发现里面的地址是 0。
CPU 尝试去访问 内存地址 0。
报警！ 现代操作系统为了安全，把地址 0 附近的一大块区域设为“绝对禁区”。任何普通程序只要敢碰地址 0，硬件就会立刻向操作系统打小报告。
惩罚：操作系统收到报告，心想：“这程序疯了，居然想往地址 0 写数据！” 于是直接一记“二向箔”把你的程序杀掉，并在屏幕上留下：Segmentation fault (core dumped)。
malloc 发生并失败：它没有变出内存，但它返回了一个 0。
赋值发生：x 成功变成了 0（空指针）。
解引用崩溃：当你尝试用 x[0] 访问地址 0 时，因为那是禁区，程序当场去世。
