int main () {
	int x[5];
	x[0] = 254; x[1] = 649; x[2] = 971; x[3] = 1678;
	unsigned char *y = (unsigned char*) x;
	// we'll run some print statements here
}
printf("%d\n", x[4]); garbage
printf("%d\n", x[15]); n/a
printf("%d\n", *y); 0
printf("%d\n", *(y+3)); 254

x[4] —— 合法位置，但没给值
数组定义： int x[5];（这意味着 x[0], x[1], x[2], x[3], x[4] 都是合法分配给你的空间）。
代码赋值： 你只给 x[0] 到 x[3] 赋了值，漏掉了 x[4]。
结果： 既然 x[4] 是属于你的合法地盘，CPU 去读它是没问题的，不会报错。但因为你没放东西进去，那里存的是之前程序用剩的“陈年旧数”。
结论： 这叫 Uninitialized Value（未初始化值），在题目里对应的术语是 garbage。
x[15] —— 非法位置，越界入侵
边界限制： 你的地盘只到 x[4] 为止。x[15] 已经完全超出了你申请的 5 个连续空间的范围。
C标准： 访问 x[5] 及往后的任何位置都属于 Out of Bounds（数组越界）。在 C 语言中，这被定义为 Undefined Behavior (UB)。
结果： 就像翻译里说的，虽然在栈上它可能正好读到别的东西，但从逻辑和规范上讲，它的结果是“不确定的”、“不可预测的”。
结论： 题目要求“如果行为不确定（uncertain），请输入 n/a”。

Q1.8: 0 (错误：你填了 254)
解析： 关键点是大端序。x[0] 是 254，十六进制为 0x000000FE。在大端序中，内存布局为：0x1868: 00, 0x1869: 00, 0x186A: 00, 0x186B: FE。y 指向 0x1868，所以 *y 读到的是 0。
Q1.9: 254 (错误：你填了 1)
解析： y+3 指向 0x186B。如上所述，该字节是 0xFE，十进制就是 254。

指针没有"."，不能用.访问指针，比如a.xxx不行，只能a
如果访问结构体指针里面的东西可以用a->xxx或者(*a).xxx

1. char *a = "hello"; —— 它是指针（指路牌）
当你这样写时，编译器做了两件事：
在只读内存区放了 "hello\0"。
在栈上给了你一个名为 a 的变量，它是一个指针，里面存的是字符串的首地址。
sizeof(a)： 你量的是这个“指路牌”本身的大小。在 32 位系统上，所有指针都是 4 字节；在 64 位系统上是 8 字节。它跟你指向的字符串有多长完全没有关系。
2. char a[] = "hello"; —— 它是数组（储物柜）
当你这样写时，编译器会在栈上开辟一块连续的空间，并把 "hello" 的每一个字母（包括看不见的 \0）一个一个拷贝进去。
sizeof(a)： 你量的是这个“储物柜”的总空间。
注意！ 结果不是 5，而是 6。
为什么是 6？ 因为 C 语言的字符串必须以 \0（空字符）结尾。所以空间里放的是：'h', 'e', 'l', 'l', 'o', '\0'。
