结构体可以按值传递（Pass by Value）。
为什么它可行？
在 C 语言中，如果你返回一个结构体（而不是指针），编译器会执行全量拷贝。
函数在内部创建了 v。
v.data 确实用了 malloc，所以这块存储具体数字的内存是在堆上的，不会随着函数结束而消失。
当你 return v; 时，编译器把 v 里的所有成员（size 和 data 指针地址）原封不动地复制给了调用它的那个变量。
通俗地说： * bad_vector_new 是给了你一个已经拆迁的地址。
also_bad_vector_new 是把整个**箱子（结构体）**复印了一份寄给你。箱子里那张写着“堆内存地址”的纸条也被复印了，所以你依然能找到那块 malloc 出来的内存。


在 C 语言中，你通常不需要（也不能）检查 *v == NULL。
在你的代码里：
v 的类型是 vector_t *（指向结构体的指针，即地址）。
*v 的类型是 vector_t（具体的结构体对象，即内容）。
NULL 在 C 语言里本质上是一个“零地址”。你可以检查一个“地址”是不是空的，但你不能检查一个“结构体实体”是不是空的。
比喻：
v 是信封上的地址。你可以检查地址是不是写着“无此地”（v == NULL）。
*v 是地址对应的房子。房子就在那儿，它里面有客厅（size）和卧室（data）。你不能问“这个房子是不是空地址”，因为房子本身不是地址，它是一个实体。

需要在末尾加 *v = NULL 吗？
这是一个非常有深度的问题，涉及到**“悬空指针”（Dangling Pointer）的防护，但在这里直接写 *v = NULL 会导致编译错误**。
为什么 *v = NULL 是错的？
你的函数定义是 void vector_delete(vector_t *v)。
v 是一个地址。
*v 是这个地址对应的结构体实体。
类型不匹配：你不能把一个 NULL（空地址）赋值给一个“结构体”（房子）。就像你不能把“无”这个概念赋值给一栋实体房子一样。
那么写 v = NULL 有用吗？
C
void vector_delete(vector_t *v) {
// ... 释放内存 ...
v = NULL; // 没用！
}

如果函数返回的是**xx，可以说是*x = NULL，即处理悬空指针
