这里size是数组的长度

1. 为什么 v->size - 1 < loc 是个陷阱？
在 C 语言中，size_t 是一个无符号整数（只能是 0 或正数）。
想象一下如果你的向量是空的（v->size 等于 0）：
你执行 v->size - 1。
在数学上， 0−1=−1。
但在 size_t 里，没有 -1！ 计算机为了处理这个减法，会让数字发生“回绕（Wrap-around）”，变成一个天文数字（比如 18,446,744,073,709,551,615）。
如果你此时想获取 loc = 0 的位置：
判断语句变成了：如果 (那个天文数字 < 0)。
结果是 False（因为那个大数肯定大于 0）。
程序会跳过 if，直接去执行 return v->data[0];。
崩了！ 因为你的向量明明是空的，你却去访问了第 0 个位置。

v->size < loc	报错 (漏掉了相等)

v->size < loc + 1：虽然好，但有隐患
优点：当 size = 0 时，0 < 0 + 1 是 True，能成功拦截。这比你之前的 size - 1 进步了一大截！
隐患（溢出）：如果 loc 恰好是电脑能表示的最大整数（比如 SIZE_MAX），那么 loc + 1 就会变成 0（溢出回绕）。
此时判断变成了 v->size < 0。
结果一定是 False。
然后程序会尝试访问 v->data[最大整数]，瞬间崩溃。
