2.1 内存分段对应关系
(a) 静态变量 (Static variables)
位置：Static（静态区）
解释： 无论是在函数内外，只要使用了 static 关键字，该变量就会在程序运行期间一直存在。
(b) 局部变量 (Local variables)
位置：Stack（栈）
解释： 函数内部声明的普通变量。当函数被调用时，它们在栈上“压入”；当函数返回时，空间自动释放。
(c) 全局变量 (Global variables)
位置：Static（静态区）
解释： 在所有函数外部定义的变量，生命周期贯穿整个程序。
(d) 常量 (Constants)
位置：Code, Static, 或 Stack
详细解释：
Code (代码区)： 像 x = x + 1 中的数字 1。编译器会将这种简单的数值直接写进机器指令里。预处理器宏（如 #define y 5）也是如此，它们在编译时直接被替换成数值并嵌入指令。
Static (静态区)： 例如在函数外定义的 const int x = 1;。虽然它是常量，但它作为一个有地址的变量存在于静态存储区。
Stack (栈)： 例如函数内部定义的局部变量 int total = 0;。虽然这里的例子没写 const，但即使是 const int local_const = 10;，它也会作为局部变量存在于栈上（只是编译器会阻止你修改它）。
(e) 机器指令 (Machine Instructions)
位置：Code（代码区）
解释： 编译后的二进制代码，CPU 执行的指令全部存在这里。
(f) malloc 的结果 (Result of malloc)
位置：Heap（堆）
解释： 程序员手动请求的动态内存。如果不手动 free，它会一直占用直到程序结束。
(g) 字符串字面量 (String Literals)
位置：Static（静态区，通常是只读数据段 Read-only Data）
深度辨析：
方式一：char* s = "string";
"string" 存储在 Static 区域且不可修改。
指针 s 本身如果是局部的，则在栈上。
方式二：char s[7] = "string";
这被称为字符数组。编译器会先在 Static 区存一份字面量，然后拷贝一份副本到 Stack（栈） 上的数组中。
关键点： 这种方式生成的字符串是可修改的 (mutable)，因为它存放在栈上。

为什么必须在 Static 区存一份“原件”？
想象一下，你的 char s[7] = "string"; 是写在一个函数内部的：
C
void my_function() {
char s[7] = "string";
s[0] = 'k'; // 修改它
}
栈（Stack）是动态的： 每次你调用 my_function 时，系统都会在栈上临时分出一块空间给 s。当函数执行完，这块空间就被回收了。
下次调用怎么办？ 当你第二次调用这个函数时，栈上又会分出一块新的、干净的空间。这时候，程序得知道往这块新空间里填什么初始值。
Static 区就是“模板”： 编译器必须在二进制文件中找个地方把 "string" 这几个字节存好。这个地方就是 Static 区（只读数据段）。它就像是复印机的原件，每次函数运行，程序就从这里“复印”一份数据到栈上。
