1. 编译器 (Compiler): 从抽象到具体
编译器是“翻译官”，它最核心的任务是理解你的逻辑并将其适配到特定的硬件架构上。
输入： 高级语言（如 foo.c）。
过程： 词法分析、语法分析、语义检查，以及最重要的代码优化。
关键点： 它是 ISA（指令集架构）相关的。同样的 C 代码，编译给 RISC-V 和编译给 x86，生成的汇编代码完全不同。
输出： 汇编文件（foo.s）。
2. 汇编器 (Assembler): 从符号到机器码
汇编器是个“打表员”，它把人类能看懂的助记符（如 addi, jal）转换成二进制指令。
处理伪指令： 比如把 li (Load Immediate) 分解为真正的硬件指令（如 lui + addi）。
两个关键表：
符号表 (Symbol Table): 记录当前文件内定义的“外部可见”的符号（函数名、全局变量）及其在文件内的相对偏移地址。
重定位表 (Relocation Table): 记录哪些地方的地址目前是“空缺”的。比如你调用了 printf，汇编器不知道 printf 到底在内存哪个位置，它就在这里打个“补丁标记”，留给链接器去填。
输出： 目标文件（foo.o），即机器语言模块。
3. 链接器 (Linker): 拼图与修补
链接器是“总装师”，它把多个 .o 文件和库文件（.lib 或 .a）缝合成一个整体。
符号解析 (Symbol Resolution): 检查是否所有的“坑”都有人填。如果你调用了 func() 但没定义，链接器就会报错 undefined reference。
重定位 (Relocation): 这是最关键的一步。它把各个 .o 文件的 text 段（代码）并在一起，把 data 段（数据）并在一起，然后修正那些打过补丁的地址。现在所有的函数调用都指向了最终的绝对地址。
输出： 可执行文件（a.out 或 foo.exe）。
4. 加载器 (Loader): 赋予生命
加载器是操作系统的一部分，它负责把磁盘上的死文件变成内存中活的进程。
内存布局规划：
Text (代码段): 从磁盘拷贝进来，通常是只读的。
Data (数据段): 初始化好的全局变量。
Stack (栈): 设置栈指针 sp，为函数调用预留空间。
Heap (堆): 初始化动态内存分配区域。
寄存器初始化：
按照 ABI (应用程序二进制接口) 标准，将命令行参数（argc, argv）放入特定的寄存器（在 RISC-V 中通常是 a0 和 a1）。
清空其他通用寄存器，确保环境干净。
跳转： 最后，加载器执行一个跳转指令，指向程序入口点（通常是 _start，它会调用你的 main 函数）。

当你在命令行输入./a.out helloworld时，操作系统需要一种方式把hello和
world这两个字符串传递给你的C程序。
以下是具体的拆解：
1.为什么涉及堆栈指针(sp)？
加载器不仅仅是将代码拷贝到内存，它还需要为程序创建一个运行时的环境。
·物理存储：你在命令行输入的参数（字符串）需要找个地方存着。加载器会把这些字符串压
入栈（Stack）的最顶部。
·设置 sp：加载器会初始化堆栈指针寄存器（在RISC-V中是sp），使其指向栈顶。这样当
你的程序开始运行并调用函数时，它就知道从哪里开始分配局部变量。
2.α0和αl是什么？
在RISC-V的ABI（应用程序二进制接口）规范中，寄存器是有分工的：
·α0到α7：用于传递函数参数。
·α0：通常存放第一个参数。
·α1：通常存放第二个参数。
当你写int main（int argc，char *argv[]）时，这其实是一个函数调用。加载器扮演了"调用
者"的角色，按照约定把参数塞进寄存器：
a0=argc:
加载器数一下你输入了几个词（包括程序名本身）。比如./a.outhello，argc就是2。
加载器把2这个整数放进a0。
.al=argu:
argv是一个指针数组（指向字符串的指针）。加载器在栈上准备好这个数组，然后把这个
数组的首地址放进α1。
3.完整的"交接”画面
想象一下程序启动前的最后一秒，内存里的样子：
1．栈底（高地址）：存着“./a.out"、"hello"、"world"这些原始字符串。
2.紧接着：存着一个指针数组，第一个指针指向"./a.out"，第二个指向"hello".
3.寄存器状态：
sp：指向栈上当前可用的位置。
a0：数值为3（假设有三个参数）。
α1：指向刚才那个指针数组的起始地址。
4.最后一步：加载器执行一条跳转指令（比如jr），把PC（程序计数器）指向程序的入口。
此时，你的main函数开始运行：
它第一件事就是去a0 找argc，去α1找argv。因为它发现这两个寄存器里已经有值了，所
以它能无缝衔接，直接知道你从命令行传了什么进来。
这就是为什么你不需要在代码里初始化argc和argv，因为Loader已经在后台帮你打理好了
这一切。

1.“任何参数”指的是什么？
当你执行一个程序时，你输入的每一串字符都被视为参数：
参数o（argv[o]）：程序本身的名字（例如./foo）。
参数1,2,..n：你跟在后面的指令或文件名（例如-v，test.txt）。
环境变量（EnvironmentVariables)：虽然你没在命令行写，但Loader也会把系统的
PATH、USER等信息一起塞进去。
这些统统属于"任何参数"的范畴。

2.为什么是"设置堆栈指针（sp)"？
栈（Stack）在内存中是从高地址向低地址增长的。Loader在启动程序前，必须先把上述那些参数
存起来，否则main函数运行起来后找不到它们。
1．拷贝字符串：Loader把./foo、-v、test.txt这些字符串逐个丢进栈顶（内存最高
处）。
2．创建指针数组：在这些字符串下面，Loader会再放一排指针（argv数组），每个指针指向
上面对应字符串的首地址。
3．最终定位sp:
因为栈里现在塞进去了这么多东西，原来的栈顶已经变了。
Loader会计算出这些数据总共占了多少字节，然后将堆栈指针寄存器（sp)向下移动到
当前数据的末尾。
"设置"的意思就是：Sp=初始栈顶－（参数数据+环境变量+
指针数组的总大小)。
3.给main函数"打样"
设置完sp后，Loader会按照ABI（应用程序二进制接口）的规定，把剩下的信息填好：
·α0寄存器：存入参数的个数（在这个例子中是3）。
·α1寄存器：存入argv数组的首地址（这个地址现在就在栈上的某个位置）。
总结
这句话的意思可以理解为：
"由于命令行参数需要存放在内存里，Loader会把它们'压'进栈中，并根据这些参数的总大小，把
Sp寄存器调整到正确的位置，确保你的程序一睁眼就能从栈上拿到这些数据。”
