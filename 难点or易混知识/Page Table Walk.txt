考虑一个64KiB的字节寻址物理内存，其内容见physical_memory.txt。由于物理内存大小为
64KiB，因此需要16位内存地址（范围从Ox0000到0xFFFF）来唯一标识内存中的每个字节。
考虑一台页大小（Page Size）为4KiB（对应12位偏移量bits）的机器。它为运行在其上的每个
程序提供32位虚拟内存空间。
该机器采用二级分级页表结构，其20位虚拟页号（VPN）被平均分配给一级（L1）和二级（L2)页
表。请注意，32位虚拟地址由20位VPN和12位偏移量（Offset)组成。相应地，16位物理地址
将由4位物理页号（PPN)和12位偏移量组成。虚拟地址和物理地址的具体划分如下所示：
		Virtual address
31-22(VPN1)	21-12(VPN2) 	11-0(Offset)
		Physical address
			15-12(PPN)	11-0(Offset)
每个页表项 (PTE) 大小为 4 字节，其相应的数据划分如下所示：
		Page Table Entry
31-30(Valid)	30-4(Other metadata (can be ignored))	3-0(PPN)
当页表项（PTE）有效时，其最高有效位（MSB）为1，最后4位对应于指向下一级页表或数据页
的物理页号（PPN）。PTE中还包含额外的元数据位，但与本题无关。
现在，假设我们在这台机器上运行两个不同的程序。巧合的是，我们观察到这两个程序访问了相同
的虚拟地址，如下所示：

# Program 1 code
lui t0, 0x00403
addi t0，t0,0x004# t0 = 0x00403004
lw t1, 0(t0)# load word from address 0x00403004

# Program 2 code
lui s0, 0x00403
addi s0, s0, (0x004# s0 = 0x00403004
lw t5, 0(s0)# load word from address 0x00403004

如你所见，两个程序都从地址Ox00403004加载一个字（Word）。然而，既然我们已经了解了虚
拟内存，我们知道尽管两个程序指向相同的地址，但这些地址是虚拟的。因此，当我们查看物理内
存时，程序1加载的数据可能与程序2加载的数据不同。在本题中，我们将尝试推导出地址转换过
程，并最终确定每个程序加载的数据。
在本题中，我们已知两个运行程序的页表基址寄存器（PTBR）的值。对于程序1，PTBR=
Ox4000；对于程序2，PTBR=Ox6000。在进行地址转换（也称为页表漫步，PageTableWalk)
时，我们需要这些值。PTBR基本上指向了转换开始时的物理内存地址。请跟随故事指引」（程序1
的转换已为你完成），并相应地回答（关于程序2转换的）问题。
我们首先将虚拟地址Ox00403004划分为VPN1-VPN2-offset字段。我们先写出完整的32位地址，
然后进行相应的拆分。
对于接下来的4个问题，请使用二进制编写答案，不要带0b前缀，也不要加空格。
Q1.写出0x00403004对应的32位二进制。
00000000010000000011000000000100
Q2.根据虚拟地址划分，对应的VPN1是什么？写出整个10位字符串。
0000000001
Q3.对应的VPN2是什么？写出整个10位字符串。
0000000011
Q4.对应的偏移量（Offset）是什么？写出整个12位字符串。
000000000100
现在我们可以开始转换了。对于程序1，我们已知PTBR（页表基址寄存器）的值为Ox4000。这
指向了程序1的一级（L1）页表。查看物理内存的内容（根据提供的文本文件），我们导航到地址
0x4000。我们已经在查看L1页表项（PTE）了。请记住，页表项长4字节。根据我们之前获得的
VPN1，我们从PTBR指向的地址开始寻找第n个页表项（其中n等于VPN1的值）。记住VPN1索
引L1页表。对于程序1，我们看到对应的L1页表项是OxDEADBEEF。
数学说明：我们实际上进行的数学运算是PTBR+VPN1*sizeof（PTE）。PTBR是起始点，VPN1
是数组索引l，每个数组元素的大小为sizeof（PTE）字节。
Q5.程序2对应的L1页表项是什么？由于页表项为4字节，应填入8位十六进制数字。
0x88C4B640
由于程序1的L1页表项是0xDEADBEEF，我们检查其最高有效位（最左边的位）来查看该条目是
否有效。在本例中，它是有效的（1）。这意味着存在有效的 PPN转换，不会发生缺页异常(PageFault)。
Q6.程序2的L2页表起始地址在哪里？由于物理内存地址为16位，应填入4位十六进制数字。
0x0000
我们基本上重复之前的步骤，但这一次我们处于L2页表中，并将使用VPN2作为索引。对于程序
1，L2页表从OxF000开始。根据之前获得的VPN2，我们从该地址开始寻找第n个页表项（n为
VPN2的值）。对于程序1，对应的L2页表项是OxBOBACAFE。
数学说明：我们进行的运算是（PPN_from_L1<<12）+VPN2*sizeof（PTE）。我们将从L1获
得的PPN左移12位，使其成为16位物理地址的最高有效位。VPN2是索引，每项长度为
sizeof（PTE)字节。
Q7.程序2对应的L2页表项是什么？应填入8位十六进制数字。
0xAE99D5C2
由于程序1的L2页表项是OxBOBACAFE，我们检查最高位，它是有效的。
现在，我们检查最后4位。因为我们处于页表层级的最后一级，最后4位将是PPN，指向实际数
据所在的页面。由于该L2页表项的最后4位是0xE，因此程序1的数据页起始地址为0xE000。
我们必须再次将PPN移至物理地址的高4位，因为PPN组成了物理地址的最高有效部分。
Q8.程序2的数据页起始地址在哪里？应填入4位十六进制数字。
0x2000
最后，我们到达了程序1数据页的起始地址0xE000。现在，我们使用之前获得的偏移量
(Offset）来寻找实际数据。注意物理内存是按字节寻址的，因此偏移量每增加1，我们就移动1
字节。此外，程序1正在执行1w（加载字）指令，因此它会从偏移量指向的地址开始加载4字节
的数据。至此，我们终于找到了程序1虚拟地址0x00403004的物理地址转换：16位物理地址是
OxE004，加载到寄存器t1的字是0xADE1B055。
数学说明：此时技术上只需从虚拟地址中复制12位偏移量。物理地址OxE004是PPN=OxE（来
自L2页表项）和Offset=Ox004的拼接。这与之前的图示说明是一致的。
Q9.程序2虚拟地址0x00403004转换后的16位物理地址是什么？
0x 2004
Q10.加载到寄存器t5（程序2）的字是什么？
0x61C061C0
至此，我们证明了即使两个程序尝试访问相同的虚拟地址，并不意味着它们会加载相同的数据。由
于这两个程序在不同的上下文（Context）中运行（即彼此独立），它们拥有不同的PTBR值。因
此，虚拟地址到物理地址的转换过程对每个程序而言是不同的。这正是本题所要演示的核心原理。
