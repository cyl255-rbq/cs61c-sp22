int *a 表示传递一个 指向 int 的指针
int *a[] 作为函数参数时，它会被解释为 指向指针的指针，即 int **a 这是因为 int *a[] 本意是一个“数组，其元素类型为 int *”
但作为参数时数组名退化为指向其首元素的指针，而首元素是 int * 类型，所以最终类型是 int **
所因在 C 语言中，作为函数参数时：void a(int a[]) 等价于void a(int *a)这两种写法完全等价，编译器都会将 int a[] 处理为 int *a

因为数组作为参数的时候会退化为指针，这时候指针指的是函数首元素的地址而不是那个数组了，所以用sizeof就不能获得那个数组的大小了，
只能获得指针存的那个地址的大小，而64位是8bytes，所以只能传递数组的时候顺带着把数组的长度也传过来
sizeof(summands)：summands 现在是一个指针（int *）。在 64 位系统上，所有指针的大小都是 8 字节。
sizeof(*summands)：*summands 是指针指向的第一个元素，即一个 int。在 C 语言中，int 通常占用 4 字节。
sizeof 确实可以返回整个数组的大小，但前提是：编译器在编译那一行代码时，必须明确知道它是一个定长数组。
一旦你把数组作为参数传给函数，这个“身份”就丢失了。我们来对比两种情况：
1. 会返回整个大小的情况：本地声明
当你直接在代码里定义一个数组时，编译器记住了它的长度。
void test() {
    char a[] = "61C";         // 实际上是 {'6', '1', 'C', '\0'}
    int b[10];                // 10个int
    printf("%lu\n", sizeof(a)); // 输出 4 (3个字符 + 1个停止符)
    printf("%lu\n", sizeof(b)); // 输出 40 (10个int * 4字节)
}
在这个作用域（Scope）里，a 的身份是 “含有 4 个元素的字符数组”。
2. 不会返回整个大小的情况：函数参数
当你把 a 传给一个函数时，为了效率，C 语言会把数组“降级”（Decay）成一个指针。
void func(char a[]) {         // 这里的 a[] 其实等价于 char *a
    printf("%lu\n", sizeof(a)); // 输出 8 (在64位系统上，指针永远是8字节)
}
int main() {
    char my_str[] = "Hello!";
    func(my_str); 
} 
为什么？ 因为在 func 内部，编译器只知道 a 是一个内存地址，它根本不知道这个地址后面到底连着 6 个字符还是 600 万个字符。
所以返回summands中所有元素的总和：(有必要在指针旁边传递一个大小。)
1 int sum(int* summands, size_t n) {
2 	int sum = 0;
3 	for (int i = 0; i < n; i++)
4		sum += *(summands + i);
5	 return sum;
6 }


在 C 语言中，后缀 ++ 的优先级比解引用 * 高。
*(string + i)++会先算 ++：它会尝试去增加 (string + i) 这个地址数值。再算 *：对增加前的地址进行解引用。
正确写法是(*(string + i))++或者string[i]++


将存储在任意长度数组开头的字符串中的所有字母加一。其中n >= strlen(string) 且不会修改数组内存的任何其他部分。
1 void increment(char* string) {
2 	for (i = 0; string[i] != 0; i++)
3 		string[i]++; // or (*(string + i))++;
4 }

原题是
1 void increment(char *string, int n) {
2 	for (int i = 0; i < n; i++)
3 		*(string + i)++;
4 }
字符串的结尾是由“空终止符”（null terminator, \0）来标识的，而不是由数组大小 n 决定的。数组中拥有 n 个字符的存储空间，
并不代表存放在其中的字符串长度也是 n。原题之所以去掉 n，是因为它在考你 “是否知道 C 字符串是以 \0 结尾的” 这个核心考点
另一个需要留意的常见 Bug 是：当对值为 0xFF 的字符执行自增（+1）操作时产生的边界情况。0xFF 加 1 会溢出回到 0，
从而产生一个“空终止符”，这会无意中（由于截断）缩短了字符串。
这个 Bug 非常隐蔽，它是这样发生的：
    假设你的字符串里有一个字符的二进制是 11111111（即 0xFF）。
    你的 increment 函数执行了 string[i]++。
    在 8 位运算中，0xFF + 1 会变成 0x00。
    灾难发生了： 原本这个位置是一个有意义的字符，现在它变成了 0x00（也就是 \0）。
    之后任何调用 strlen 或 printf 的函数，走到这里都会认为“字符串结束了”，你后面的数据虽然还在内存里，但逻辑上丢失了。
假设你的字符串是："AB" + 0xFF + "CD"
内存里是：['A', 'B', 0xFF, 'C', 'D', \0]
调用 increment 后，内存变成了：['B', 'C', 0x00, 'D', 'E', \0]
此时如果你调用 printf，它只会打印出 "BC"，后面的 "DE" 被你“亲手杀掉”了，因为中间多出了一个原本不存在的结束符。

并不是 Java 和 Python “没有”赋值表达式，而是它们为了安全性，给赋值操作加了厚厚的“防弹衣”。
我们来拆解一下这三者的区别：
1. Python：语句 vs 表达式
在 Python 中，普通的 = 被定义为 Statement（语句），而不是 Expression（表达式）。
    为什么不行： Python 强制规定语句不能出现在需要表达式的地方（比如 if 后面）。这是为了完全杜绝你把 == 错写成 =。
    但是： Python 3.8 引入了 “海象操作符” :=（Walrus Operator）。它专门用于在表达式里赋值。
        if (x := 3): 在 Python 里是合法的！它模仿了 C 的行为，但用不同的符号来提醒你：“注意，我在这里赋值了！”
2. Java：类型安全的铁律
Java 里的 = 其实和 C 一样，也是一个表达式（会返回值）。但 Java 有个“死脑筋”：if 括号里必须是 boolean 类型。
    为什么 if (x = 3) 不行： x = 3 的结果是整数 3。Java 会报错：“兄弟，3 是整数，不是 true/false，我不认识！”
    但是（危险点）： 如果 x 是 boolean 类型，Java 就允许你这么干：
    boolean locked = false;
    if (locked = true) { // 合法！赋值结果是 true，if 永远成立
        // 这里的代码永远会执行，也是 Java 里常见的 Bug
    }
3. C 语言：底层的自由（与危险）
C 语言之所以被称为“披着高级语言外壳的汇编”，是因为它在设计时几乎没有“布尔（Boolean）”这个独立类型。
    C 的逻辑： 非零即真。
    赋值的结果： x = 3 的结果是 3。
    组合拳： 因为 3 不是 0，所以 if (3) 在 C 看来就是 if (true)。
而我的解法：
void copy(char *src, char *dst) {
	while (*src != '\0')
		*(dst++) = *(src++)；
	*dst = '\0'；
}

C 是“按值传递”的。如果你想传递任何东西的“引用”，你应该使用指针。在 C 语言里，当你把变量传给函数时，
函数拿到的永远是一个副本（拷贝）。如果你传一个指针，函数拿到的也是“地址这个数值”的副本。但因为这个
副本指向的是同一块内存，所以你能在函数里修改原始数据。

1. 指针：它是一个“真实存在的盒子”
当你写 int *ptr = 0x61C; 时：
    内存里真的拿出了 8 个字节，做成了一个叫 ptr 的盒子。
    这个盒子有自己的居住地址（假设是 0x100）。
    盒子里装的内容是 0x61C。
结论：
    ptr 求值：得到的是盒子里的内容（0x61C）。
    &ptr 求值：得到的是盒子自己的地址（0x100）。
    所以：&ptr != ptr（除非你把指针指向了它自己，那属于特殊操作）。
2. 数组名：它只是一个“地址标签”
当你写 int arr[3] = {10, 20, 30}; 时（假设数组从 0x200 开始）：
    关键点：内存里没有一个专门叫 arr 的盒子来存地址。
    arr 只是一个符号，代表这块内存的开头。
结论：
    arr 求值：C 语言规定，数组名求值就是它首元素的地址（0x200）。
    &arr 求值：对整个数组取地址。既然数组是从 0x200 开始的，它的地址自然也是 0x200。
    所以：数值上 &arr == arr。

如果你在处理大数据块，传递指向堆内存的指针比传递数据本身更高效且更专业（想象一下：
带着整个图书馆走 vs 只带着图书馆的地址）。在内存布局中，堆向上增长，栈向下增长，当可用内存耗尽时，它们会“相遇”。
