Q3：我们在两个线程上运行以下代码：
//提示：以下变量在 #pragma 指令之外声明 
// 因此，这些变量在所有线程中共享。
int y = 0;
int x = 3;
#pragma omp parallel
{
	while(x > 0) {
		y=y+1;
		x=x+1;
	}
}
请注意，表达式 y = y + 1 等价于三条指令：加载 y 的值，加 1，并将结果存储到 y 中。
其他线程可以在这些指令之间执行。此外，y 是一个共享变量，这意味着一个线程对 y 所做的
任何更改都会被其他线程看到。变量 x 也同样如此。请在回答以下问题时利用这一特性。
如果您能先回答问题 2，可能会对回答此问题有所帮助，因为您可以想象一下将 C 代码分解为汇编代码，
以便进行更细致的分析。

可以改写成汇编代码为:
loop:
blt tx, x0, end
lw t0, 0(s0)
addi t0, t0, 1
sw t0, 0(s0)
lw t1, (s1)
addi t1, t1, -1
sw t1, 0(s1)
j loop:
你只有是在sw的时候，才能制造冲突去顶掉变量x/y的值，lw不行，因为lw是把值存到寄存器里
Q3.1：代码运行后，y 的最小值是多少？
1
答:t0是私有变量，互相不影响，所以y最小是1，即x在线程1的x减到0以后，此时别的线程保存y，顶替了之前的y，
这里最少为1，因为在sw之前有个+1
Q3.2：代码运行后，如果 x 的初始值不是 3 而是 10，y 可以包含的最大值是多少？

1初始状态：x=З，y=0。
2第一步（保存旧时代的光辉）：线程2刚进循环，把当前的×=3读到了自己的私有寄存器
里。然后线程2睡着了。
3第二步（线程1疯狂空耗）：线程1疯狂运转，连续循环了3次！它把×一路从3减到了0，
并且让y增加了3（此时=3，x=0）。
第三步（时空重置！）：线程2醒过来了。它执行x=x－1。由于它寄存器里存的×是
刚才保留的 3，它算出来的结果是 3－1=2！
5第四步（致命一击）：线程2把2写回了共享内存x。天亮了，原本已经被线程1扣到0的
全局变量×，突然被线程2强行拔高回了 2!
第五步（无限套娃）：既然×变成了2，原本准备收工的线程1抬头一看：？x怎么又是
2了？那我就继续循环吧！线程1又顺着2->1->0循环了2次，让y又加了2。
在这个过程中，线程2每次只要在线程1快把×扣完的时候醒一下，用旧值减1写回去，就能
强行把×的寿命延长。
真正的y最大值公式为：
Max(y)=Xinit(线程2) 十[Xinit × (Xinit +1)]/2(线程1)
当x=3时:3+(3+2+1)=3+6=9。
当x=10时:10+(10+9+8+...+1)=10+55=65。
线程2贡献了正常完整的3次循环，而线程1因为时空反复重置，被迫多跑了3+2+1=6次循环，最终合
体变成3+6=9！

如果两个一起跑，选择每次顶替一次x的减少，这样才只是3×2=6，不为最大
