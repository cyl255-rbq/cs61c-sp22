规则是对的，但“保存”并不等于“必须存入栈”。
让我们看看为什么在 map 的代码里，我们看起来“没存 a0”，但实际上却遵守了规则。
1. “Caller-saved” 的真实含义
规则说 a0-a7 是 Caller-saved，意思其实是：
“如果你（调用者）在 a0 里放了宝贝，而你跳走（jal）回来后还想要这个宝贝，那你在跳走前必须把它存起来。如果你不存，被调用者把 a0 弄脏了，你不能怪别人。”
关键点：如果你回来后不再需要那个“旧的” a0，你根本不需要存它！
2. 在 map 函数中，a0 的寿命极短
看看你的 map 逻辑：
准备参数：你把 node->value 放进 a0。
跳走：jalr ra, s1, 0。
回来：此时 a0 变成了函数的返回值（比如平方后的数）。
重点在这里： 你在跳走之前，需要 a0 原来的值（那个 3）吗？不需要了，因为你已经把它传给函数了。你在跳回来之后，需要 a0 原来的值吗？也不需要了，因为你正等着拿它的返回值（那个 9）去更新内存呢。
3. 为什么大家总觉得 a0 “没被保存”？
因为 a0 有双重身份：它是参数，也是返回值。
作为参数：它的任务在 jal 的那一瞬间就完成了。
作为返回值：它在 jr ra 的那一瞬间诞生。
既然旧的 a0（参数）已经没用了，新的 a0（返回值）正我们要的，我们干嘛还要费劲把它存到栈里再取出来呢？直接用返回值覆盖参数，是计算机最完美的“废物利用”。
4. 什么时候“必须”保存 a0？
假设你的代码是这样的：
Code snippet
# 我想计算 (x + 1) * x
mv a0, s0        # a0 = x
jal ra, add_one  # 调用函数，返回 a0 = x + 1
mul a0, a0, ???  # 此时我想乘原来的 x，但我发现 a0 已经变成 x+1 了！x 丢了！
在这种情况下，你就必须在 jal 之前保存 a0（或者像我们之前做的那样，一开始就把 x 存在 s0 这种保险箱里）。
5. 总结：关于那个“规则”的终极解释
当你读到“调用者需要保存 a0-a7, t0-t6”时，你应该在脑海中自动补全一句话：
“……前提是你以后还打算用这些寄存器里现在存着的这个值。”
对于 t 寄存器：通常我们在里面存临时计算结果，跳回来后还要接着算，所以经常要存。
对于 ra：你跳回来后必须靠它回家，所以必存。
对于 a0：通常跳回来后我们要的是它的新值（返回值），所以通常不存旧值。

方案 A：坚持用 t0 (Caller-saved 逻辑)
如果你在循环里调用函数，你必须在每次循环里都存取一次内存。
Code snippet
loop:
sw t0, 0(sp)       # 存 (第 1 次)
jal ra, func
lw t0, 0(sp)       # 取 (第 1 次)
...
sw t0, 0(sp)       # 存 (第 2 次)
jal ra, func
lw t0, 0(sp)       # 取 (第 2 次)
j loop
方案 B：改用 s0 (Callee-saved 逻辑) —— 推荐做法
你只需要在函数的开头和结尾存取一次，中间可以随便跳！
Code snippet
# --- Prologue ---
addi sp, sp, -4
sw s0, 0(sp)           # 全程只存这一次！
loop:
mv s0, a0          # 这里的 s0 在 jal 后绝对安全
jal ra, func
add t1, s0, t1     # 直接用 s0，不需要 lw！
j loop
# --- Epilogue ---
lw s0, 0(sp)           # 全程只取这一次！
addi sp, sp, 4
